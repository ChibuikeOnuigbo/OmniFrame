# OmniFrame editor finishing goal

Goal: make the editor fast, understandable and reliable across the web and desktop
surfaces, with creative tools that are editable, previewable, exportable and testable.
A catalog count alone is not completion. Every new effect must render in the shared
preview/export path, have usable controls, preserve undo/project persistence and show
its intended visual result on real footage.

## Current work

- [x] Cel animation entry, onion skins, duplicate/clear cel and path-based Draw on.
- [x] Effect View Mask: rectangle, circle, ellipse, text, polygon, split; inside/outside,
  rotation, feather and opacity.
- [x] Star and hexagon View Masks in browser and headless rendering; text font selector
  and numeric polygon point editing.
- [x] Draw polygon and freehand effect masks on the program monitor; drag points,
  snap to quarter guides and smooth outlines with an adjustable cubic curve.
- [x] Add individually draggable Bezier handles with reset and shared preview/export geometry.
- [ ] Add Krita-style perspective/curve assistants and rulers for precise drawing.
- [x] Optional color and offset feather controls with blue/black/white presets and
  verified alpha/color pixels in headless rendering.
- [x] Profile 4K colored-feather headless rendering and bound pixel work to the mask.
- [ ] Add a GPU path or another large speedup for real-time 4K colored feathering.
- [ ] Text handwriting reveal with editable glyph paths and a useful preset set.
- [ ] Card flip and hologram families with different motion, controls and test renders.
- [ ] Squash bounce/roll with floor and collision controls; dust, water reflection,
  aura and glowing-eye effects with masks, timing and real preview/export parity.
- [ ] Verify interaction, performance and native desktop builds across supported OSes.

For each item, acceptance requires an actual rendered sample, relevant pixel or
motion check, live UI test where needed, and a review of failure cases. Source links
or recipe IDs do not count as watched tutorials or validated effects. This ledger is
updated as work passes those checks; unchecked items remain open.

14 November feather check: a blue feather changes edge RGB, and an inward/outward

Colored feather is opt-in; its canvas pixel readback still needs 4K performance

Visual comparison: qa-output/effect-mask-feather/contact.png (plain, blue and

14 November 4K profiling: a 3840×2160 circular blue feather, three headless runs
on the same machine, took 842–1071 ms/frame and about 975 MiB RSS before bounded
pixel readback; after cropping the optional tint/offset work to the mask area, it
took 690–833 ms/frame and about 684 MiB RSS. Circle, inverted ellipse and curved
custom mask outputs matched the previous renderer pixel for pixel at 512×384.
Run `node --expose-gc qa/effect-mask-4k-benchmark.mjs` to repeat the current
measurement. These are headless CPU figures, not browser playback measurements;
real-time 4K colored feathering remains open.

14 November second 4K pass: cropping each temporary shape canvas to its masked
region reduced the same sample to 459–645 ms/frame and about 542 MiB RSS. Circle,
inverted ellipse, curved custom path and text mask outputs matched the previous
renderer pixel for pixel at 512×384. The next pass bounded the union matte too.

14 November third 4K pass: ordinary masks now use a bounded union matte and clear
the rest of the frame explicitly; inverted masks retain full-frame composition.
The same headless sample took 325–374 ms/frame and about 381 MiB RSS. Seven
single, edge, multiple, split, text and custom mask comparisons matched the
previous renderer pixel for pixel at 512×384. The headless sample remains much
slower than a real-time 4K frame budget, and browser/GPU timing is unverified.
The same benchmark with `--inverted` took 501–954 ms/frame; inverted masks keep
a full-frame matte but restrict tint readback to the edge region.
