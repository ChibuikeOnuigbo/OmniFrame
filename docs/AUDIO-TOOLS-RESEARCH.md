# Audio isolation research and implementation map

Last checked: 2026-10-12.

## Reference products

- **AudioStrip isolate** — https://www.audiostrip.com/isolate. The service documents VBSplitz and Demucs 4 options, vocal/instrumental and four-stem layouts, lead/backing vocal layouts, drum sub-stems, common MP3/FLAC/WAV formats, clipping prevention and key/BPM detection. Its wider product lists noise removal, batch isolation and mastering. See also the [AudioStrip feature page](https://www.audiostrip.com/).
- **DeVoice** — https://devoice.io/remove-background-noise. Its page presents audio/video cleanup, noise reduction, vocal/instrument separation and transcription. The upload widget could not be tested from this environment, so these are product claims, not a live quality evaluation.
- **VocalRemover.org** — [AI splitter](https://vocalremover.org/splitter-ai) offers a four-stem/rebalancing workflow; [Pitch](https://vocalremover.org/pitch) and [Key & BPM Finder](https://vocalremover.org/key-bpm-finder) describe independent pitch/tempo plus key/scale/BPM analysis; [Cutter](https://vocalremover.org/cutter) supports trims and fades; [Joiner](https://vocalremover.org/joiner) provides fragment selection and crossfades; [Voice Recorder](https://vocalremover.org/voice-recorder) includes trim, EQ and reverb. Their pages are JavaScript-rendered, so the accessible feature descriptions came from search excerpts rather than a full interactive session.

## OmniFrame implementation in this branch

- **Demucs v4** is the best installed local music separator when `public/models/htdemucs.onnx` is available. The 174 MB weights were fetched for this workspace with `npm run fetch:demucs` and remain Git-ignored; fresh checkouts should run it before building if they need the local model. The bundled weights' license is personal/research use only, so do not ship them commercially without confirming rights. It produces synchronized vocal, drum, bass and other tracks plus an instrumental reference asset. One shared peak-safety gain preserves stem balance; individual stems are not loudness-normalized separately.
- **Model-quality limit:** BS-RoFormer is a relevant high-performing music-separation model family ([paper](https://arxiv.org/abs/2309.02612); [reference implementation](https://github.com/JacobLinCool/vocal-separation)), but this build's BS-RoFormer entry is disabled and has no local weights/runtime. Demucs is therefore the best *installed local* option, not a claim of DeVoice/SOTA parity.
- **Selected-audio batch isolation** runs the current voice/instrumental settings sequentially over multiple selected audio clips and creates a synchronized result per source, avoiding several large inference workers at once. Video clips must have their audio extracted first.
- **Slowed + reverb correction** is exposed in the Audio dock and uses the existing Silero-based speed detector before separation. A manual correction-factor override is also available for unusually processed edits; output stems are restored to the original time base. The four-stem action estimates candidate vocal intervals from the separated vocal stem and maps them back to source-media time.
- **Reviewed vocal patching** is non-destructive: the user can adjust, exclude or add ranges, then create a full-length patched copy that replaces those ranges with the time-aligned instrumental stem from the same passage. Short raised-cosine crossfades reduce clicks; the original remains in the library. The source and separated tracks are muted when the patch becomes active so they are not doubled.
- **Cleanup alternatives** remain available: Omni Unified, the in-house voice denoiser, RNNoise and the fast DSP path. A/B preview and WAV download are available for generated results. Real-media fetch/decode errors now surface instead of silently returning a synthetic test tone.
- **Key/BPM helper** provides a browser-local 12-tone chroma key estimate and onset-autocorrelation tempo estimate (first 90 seconds), with half/double-time hints. Treat both as arrangement aids and verify by ear.
- **Independent pitch and tempo rendering** is now exposed in the Audio dock. Pitch can move ±12 semitones while preserving clip duration; tempo/speed can render at 50–150% while preserving pitch, with output duration changing as expected. The user can choose transient-aware mixed-music pitch shifting or formant-preserving solo-voice pitch shifting. Tempo uses transient-aware time stretching. Stereo is processed in linked mid/side components, the selected clip’s visible source range is rendered into a new WAV asset/track, and the source remains available (muted by default, unmuteable). A Web Worker keeps the CPU-heavy transform off the UI thread; processing is limited to 5-minute selections to bound browser memory.
- **Voice recorder** is available in the Audio dock. It captures up to three minutes from the local microphone and can apply low-shelf, presence and high-shelf EQ plus a synthetic room-reverb send before creating a WAV asset/clip at the playhead. The capture remains in the browser; it is not uploaded.

The UI labels VAD ranges as suggestions because melodic singing, reverb and effects can defeat speech-activity detection. Users should audition the ranges before patching.

## DeVoice comparison and source identification

The DeVoice MP3 stems are not checked out in the working tree, but they are recoverable from Git commit `22ecf32` (`Vocal_1791637488052.mp3` and `Other stems_1791637479716.mp3`). On 12 Oct 2026, I extracted them to `/tmp` without restoring the binaries into the worktree and reran the comparison with [`qa/devoice_reference_study.py`](../qa/devoice_reference_study.py); the JSON is [`qa/reports/devoice-reference-study.json`](../qa/reports/devoice-reference-study.json). Both stems decode to 60.0294 seconds at 44.1 kHz stereo. The reproducible script compares their stereo sum to the explicitly supplied source candidate and recomputes first-minute vocal metrics; source identity is supported by signal matching, not by the output filename alone:

- **UPAST (Ultra Slowed) - HELLBLADE.mp3** is 108.2514 seconds. On the first 60.00 seconds, the summed DeVoice stems match its 100 ms log-RMS envelope at **0.9894 correlation**. Full-rate mono correlation peaks at **0.9881** after a 576-sample (**13.06 ms**) stem-delay alignment; at zero lag it is −0.177. The script searches ±100 ms and records both zero-lag and aligned values.
- A previous candidate scan found **DJ UNIVXRSEL - DROLLXD SLOWED - DJ UNIVXRSEL.mp3** had a much weaker best envelope match (**0.4207**) at a different offset and 1.379× scale; that alternate-file sweep is not part of the new script's report.

This strongly identifies the DeVoice source as the **first 60.03 seconds of the UPAST track**, with a 13.06 ms decoded stem delay. On the same first 60.00 seconds, the fresh Silero-based `voice_realtrack_study.py` measurements were:

- DeVoice vocal output: **85.5% vocal-like energy / 72.0% voiced frames**; its `other` stem measured **0.1% / 0.0%**.
- Existing OmniFrame HTDemucs v3 timeline-aligned output (`evidence/voice/realworld/output-track2-keep-vocal-demucs-v3.mp3`): **46.5% / 35.8%** on its first 60.00 seconds. Its full 108.25-second report is **43.2% / 28.8%** in `qa/reports/voice-realtrack-vet-track2-v3.json`; do not mix the first-minute and full-track windows. The audio artifact is an existing output, not a new inference. These are voice-likelihood heuristics, not ground-truth separation scores.
- A previous HTDemucs v4 one-pass CPU/WASM run processed the first 60 seconds in independent **8-second timeline slices** to stay below headless Chromium's memory limit. It measured **50.9% vocal-like energy / 42.5% frames** (**2.3 dB below DeVoice** by this heuristic). Because these outer slices had no overlap and are not the app's normal three-pass long-track execution, this is directional—not a clean parity result. A single continuous 60-second WASM call crashed Chromium; the real-model UI E2E passes on a five-second fixture, but full-length low-memory CPU/WASM stability remains unresolved (the WebGPU path was unavailable in this environment).
- The real-model UI E2E was rerun on 12 Oct: **6/6 passed** on a deterministic five-second synthetic mixture—HTDemucs v4 achieved **18.19 dB SI-SDR**, **−46.30 dB music bleed**, and pause energy **17.7 dB below speech**. This validates the model/UI path on synthetic audio, not real-song quality or DeVoice parity.
- The slowed-correction E2E was also rerun on 12 Oct: **18/18 passed**. It detects ×1.45 on the 108-second UPAST track and validates exact timeline restoration, a one-pass action on short real excerpts, natural-pitch output, instrumental no-op, resampler fidelity, native-DSP parity, and model-load progress. Because of this sandbox's WASM memory ceiling, it does not rerun a full 108-second three-pass browser separation; production-strength full-track artifacts are previously recorded in `evidence/voice/realworld/README.md`.
- In the DeVoice-v3 `vet` comparison, both outputs had zero clipped samples and zero spectral-flux outliers. The study tool is a singing-sensitive heuristic, not ground truth or a replacement for listening.
- The previously measured OmniFrame natural-pitch export is **87.7% vocal-like energy / 65.0% frames**, but it is only 74.66 seconds for the 108.25-second source; it changes pitch and timing, so it is not an apples-to-apples match for DeVoice's 60.03-second timeline-aligned output.

The comparison therefore confirms a substantial **timeline-aligned separation-quality gap**; this work does not claim a DeVoice match. An experimental spectral residual-recovery helper was corrected to preserve the original vocal while adding a masked accompaniment residual; on this track the added content was only −72.1 dBFS and did not close the gap, so that heuristic was not added to the production path. ## Not claimed as implemented here

This pass does not add AudioStrip-style batch file import/mastering, DeVoice transcription, or a dedicated multi-clip cutter/joiner. Multi-selected timeline clips can be isolated sequentially, but that is not the same as a batch upload/mastering service. The new local pitch/tempo render uses transient-aware pitch shifting/time stretching (with a formant-aware pitch mode for voice); synthetic tests establish basic pitch/duration behavior, not perceptual quality or commercial parity. The recorder/EQ/reverb panel is a local basic tool, not a studio-grade vocal chain. DeVoice parity on real slowed/reverb mixes remains an open quality gap.
