# Editor QA increment — 2026-11-01

This increment turns the new Studio Looks pack into reviewable moving-video evidence and adds the requested editor workflows around it.

## Effects evidence

- `effect_vid/clips/` contains one 2-second, 320×180, 12 fps MP4 for every one of the 1,152 Studio Looks.
- `effect_vid/all-1152-studio-effects.mp4` concatenates those clips in catalog order. Measured output: 2,304 seconds, 27,648 decoded frames, 42,534,834 bytes, SHA-256 `f09d618e0c6bfbdcd252ebd5eab51877889eaa7cbc9d728d87776fa6b5e990eb`.
- `effect_vid/manifest.json` records every preset ID, editable patch, clip path, timing, decoded-frame count, distinct-frame count, and clip hash. The validation required 24 decoded frames and at least 12 distinct frames per look.
- The catalog now also exposes direct search names for Horizontal Blur, Oblique Blur, Vertical Blur, Radial Blur, Cinematic Blur, and Motion Blur. These are editable recipes on the existing shared blur kernels.

## Independent RDT recreation

`new_work_qa/RDT_recopy1.mp4` is a 25.06-second, 360×640, 24 fps edit made from seven independent segments of the downloaded Gojo source. The finished reference is analysis-only and is never used as a layer. OmniFrame MCP tools create the background/foreground layers, center-band layout, scene timings, blur and grade, screen/color-burn compositing, speed curves, animated title scale/opacity, timeline proof, and final export.

Measured output: 601 decoded frames, 601 distinct frame hashes, one AAC output stream mixed from seven scene sources, and 1,341,376 bytes. `new_work_qa/RDT_recopy1-manifest.json` records source hashes, source and timeline windows, tool workflow, project clips, and validation. `RDT_recopy1-review.png`, `RDT_recopy1-preview.png`, and `RDT_recopy1-timeline.png` are the visual review artifacts.

`new_work_qa/RDT_recopy2.mp4` is the corrected second pass. Every title uses its scene video as a moving glyph matte, applies the negative/brightness/contrast/saturation treatment only inside the glyphs, removes the solid white core, and uses clip-local blend hold keys. Reference samples have bright title cores, so Screen is the closest supported compositor inference; Color Burn is retained for two darker titles and as the short entrance mode on Screen titles. Linear Burn is not claimed because the current Canvas compositor does not expose it. The edit uses seven different background/foreground looks and seven speed curves rather than one repeated preset.

Measured second-pass output: 25.041667 seconds, H.264 360×640 at 24 fps, AAC audio, 601 decoded frames, 601 distinct frame hashes, 1,293,798 bytes, and SHA-256 `febe6a61368bc73def09ae3c2bea5f7bd16dbefa91f059c11fcbfbc831178c87`. `RDT_recopy2-manifest.json`, `RDT_recopy2-review.png`, `RDT_recopy2-preview.png`, and `RDT_recopy2-timeline.png` are the review evidence.

## Editor features

- Blend modes are grouped in the inspector. A clip can hold discrete blend-mode keyframes, and browser playback plus headless MCP export evaluate the same clip-local keys. The MCP `blend_set` tool accepts an optional key time; `edit_element` validates and round-trips `blendKeys`; `data_dump` exposes them.
- The live MCP `preset_preview` command returns an actual PNG rendered by the editor for effects, transitions, LUTs, and text presets without committing the preview. The headless command renders effects, LUTs, and text; transition preview remains on the live bridge because it uses browser playback and an adjacent cut.
- `list_presets` is paginated and reports full effect, LUT, text, transition, shake, speed, ratio, and pillar catalogs.
- Text & Title has a Video Fill picker for imported videos plus inside-only Negative, brightness, contrast, saturation, solid-core opacity, and source-time controls. Browser playback uses an independent decoder for the duplicated matte layer, avoiding seek conflicts with the underlying clip. The live/headless MCP `text_crop_video` command creates the same editable setup.
- The Media panel has one GIF Library for GIPHY and Klipy with provider switching, trending/search, preview grid, attribution, source links, loading/error/download states, and editable MP4 import. Separate keys live in Settings → AI & APIs and are held only for the browser tab. A live key is required; no credential is bundled in the repository.

## Verification and limits

TypeScript and the production web build pass. Browser QA covers the standard editor workflow, viewport interactions, moving video-inside-text playback, GIPHY/Klipy settings/search/download/import, live MCP preview, preview performance, proxies, and the desktop frontend's Tauri info/ping/fullscreen contracts. Headless QA covers project reset, compositor patches, speed curves, blend-key pixels, video text matte rendering, and preset-preview isolation.

The current Debian runner does not contain Rust/Cargo, WebKitGTK 4.1 development files, or rsvg2. It cannot compile or launch the native Tauri shell. `tauri info` reports those three missing prerequisites. The desktop frontend and IPC contract are tested in a controlled Tauri bridge harness; Linux, Windows, and macOS installer compilation remains assigned to the repository desktop CI matrix.
