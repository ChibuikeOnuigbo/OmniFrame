# Strict UI sweep — findings

Generated by four detectors. Run them with the dev server up:

```
npx vite --host 0.0.0.0 --port 5173
node qa/ui-strict-audit.mjs       # 14 UI rule classes
node qa/ui-overflow-audit.mjs     # does it fit
node qa/ui-affordance-audit.mjs   # can you hit it and name it
node qa/source-scan.mjs           # defects only visible in source
```

## Where the count came from

The first honest number was not 500. The app boots with **zero tracks and zero
clips**, so a plain tab walk measured an empty shell — 63 controls and almost
no sections. `qa/seed-project.mjs` now populates a real project (tracks, clips,
a selection, markers, a text layer) before anything is measured, which takes the
walked surface from 63 controls to 102 per tab.

Across 4 viewports × 10 tabs × 7 overlays × every reachable submode, the strict
audit's first real run reported **1,377 findings / 394 root defects**, plus
**192** from the source scan — 586 root defects in total.

## Root causes, not symptoms

**Two colour tokens caused 271 findings.** `ink-400` (#55617a) measured
2.80–3.20:1 and `ink-500` (#3c475d) 1.87–2.13:1 on the dark surfaces, both far
under WCAG AA 4.5:1. Nearly every secondary label in the app was affected.
Rebuilt as #77839c / #94a1b8 / #b6c1d4 — same hue, same ordering, all ≥4.5:1.

**One colour could not be fixed by changing it.** `text-brand` (#6d5efc) fails
as text (4.07–4.41:1) but brightening it drops white-on-brand buttons from
4.51:1 to 3.86:1. No colour satisfies both roles, so they are separate tokens:
`brand` for fills, `brand-400` for text. 122 usages moved.

**A silent Tailwind bug.** `h-8.5`, `w-8.5`, `h-7.5`, `h-6.5` are not in
Tailwind's default spacing scale, so those classes generated no CSS at all. Dock
tabs authored as 34px targets rendered at exactly the 17px icon they contain.

**Two floating toolbars buried the preview's controls.** Both were centred at
the top with a max-width written against `100vw` while living inside the much
narrower preview viewport, so they always reached the top-right view chrome.
SelectionSubToolBar moved to the bottom; DrawingToolbar moved below the chrome
row.

**19 instances of 8px type** — below any readable minimum — raised to 10px.

**The shared `Slider` component never set a name**, so every slider built from
it was announced as just "slider".

## Regrouping

The drawing panel rendered all 77 of its controls flat in one scrolling column.
It is now six collapsible sections, with the tool group further split into
three. Every section defaults to **open** — they are all primary controls for
that panel, and collapsing them hid the tools the panel exists to expose (which
broke four e2e suites). The grouping and outline are the improvement; collapse
is left to the user.

Reusable component: `src/components/PanelSection.tsx`.

## Detector bugs found along the way

Seven rules reported fiction before they reported truth. Each is documented at
the point of the fix:

- **D05** measured geometric overlap, flagging closed panels that are
  translated out of view and popovers that are *meant* to cover the page. Now
  asks the browser via `elementFromPoint` whether a control receives its own
  centre click, and skips controls clipped out of their scrolling ancestor.
- **R03** anchored its number match at the start of the string, then stripped
  the slider's own value from the text — deleting the readout it was searching
  for.
- **D02** read computed `gap`, but `space-y-*` spaces with margins.
- **D04** flagged every `.sr-only` element, where 1px clipping is the point.
- **C02** counted zero-width svgs as 0px and 1px "icons".
- **T01** flagged tooltips on `truncate`d labels, where repeating the full text
  is doing real work.
- The audit forced side panels open below the 1080px breakpoint where
  `Studio.tsx` closes them, producing overlaps the app does not allow.

## What remains

19 root defects, all medium or low:

- **D01 (9)** — groups over 14 controls. Mostly tool palettes, where a dense
  grid is the correct design rather than a defect.
- **C01 (4) / C02 (2)** — control heights and icon sizes disagreeing within a
  row. Cosmetic.
- **A04 (2) / A01 (1)** — two unnamed inputs and one icon-only button with no
  visual tooltip.
- **D06 (1)** — a keyframe hint overflowing its clip parent.

Source scan's 192 are advisory by design: 155 hardcoded colours in UI files
(theme-token maintenance), 19 non-null assertions, 18 `setTimeout` without a
matching `clearTimeout`.
